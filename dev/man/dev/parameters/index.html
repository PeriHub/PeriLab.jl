Parameters

The input deck is read into typed structs. Every section and every model declares its YAML keys as an @params struct (src/Support/Parameters/Spec): type, required or default, min / max, allowed values, a quantity (documentation only; PeriLab has no fixed units) and a description.

PeriLab.InputDeck.read_input validates a deck against these declarations and reports every problem at once (unknown keys with a suggestion, wrong types, values out of range). With Strict Validation: false (or --no_strict) unknown keys are warnings instead of errors.

A model module declares its own keys and registers them under its model name, e.g.

@params "Elastic-plastic material with a constant yield stress" struct MyMaterialParams
    "Stress at which the material starts to yield"
    yield_stress::Dependent = req("Yield Stress"; min = 0, quantity = :stress)
end
__init__() = register_material("My Material", MyMaterialParams)

A docstring above a field is its description (the same as description = "..."; giving both is an error). The string between @params and struct describes the section or model itself (params_description(T)). Both end up in the JSON Schema (description), in describe and in the generated input reference; PeriHub shows them as tooltips. Every section, model and key needs one, a unit test (ut_generators_deck.jl) fails otherwise.

Write descriptions for a user filling in a form:

  • one or two sentences on what the value controls or what the model represents, starting with a verb or a noun phrase ("Stops the step once …", "Linear elastic correspondence material based on the deformation gradient");
  • do not repeat the key, the quantity, the allowed values, the default or the range, the schema shows them already; give a unit only where quantity cannot express it (degrees, counts) and a default only where it needs explaining ("-1: compute it from the stable time step").

See the templates under src/Models/*/…_template for every category.

A key that is read only for some values of another key of the same entry declares that with when:

opt("Young's Modulus X"; quantity = :stress,
    when = Dict("Symmetry" => ["orthotropic", "transverse isotropic"]))

The key is read only if every listed key has one of the listed values (exact, case-insensitive). A listed key that is not set counts with its default; without a default the condition holds. The pseudo key "\$solver" stands for the solver chosen in the same Solver / Multistep Solver step. Every listed key needs a fixed set of values: allowed, an @enum type, or schema_choices(T) for values PeriLab matches loosely or takes from a registry (the bond filter types, Symmetry). The JSON Schema emits the condition as x-perilab-when, the input reference as "only with …"; parsing ignores it. Rules that depend on a key being set ("ignored when Fixed dt is set") stay in the description.

Keys required only for some value of another key go into conditional_required(T), as Dict("Type" => ["Rectangular_Plane"]) => [keys...]; the schema adds an if/then per entry to the struct's allOf. check! still enforces them when the deck is read.

Fields are listed in declaration order (schema, describe, input reference): declare the required keys first, then the common ones, then rare or expert keys.

A solver is registered the same way. Its options struct is a subtype of SolverOptions, and the input deck names the solver by its key inside Solver (or a Multistep Solver step):

@params "Explicit solver with my time step control" struct MySolverParams <: SolverOptions
    "Factor on the stable time step"
    safety_factor::Float64 = opt("Safety Factor"; default = 1.0, min = 0)
end
__init__() = register_solver("My Solver", MySolverParams)

The solver module defines init_solver(options, params, models, bcs, block_nodes), which returns a TimeWindow and the solver's state, and two functions for the time steps:

  • prepare_solver(run::SolverRun{MySolverParams}, ctx::SolverContext) is called once before the first step and returns the solver's workspace (fields, buffers, start values);
  • time_step!(ws, run, ctx, clock::StepClock) computes one step from N to NP1 at clock.time with increment clock.dt, and returns StepFailed(reason) if the step cannot be computed.

The time loop is shared by all solvers (time_loop): it writes the results, applies Maximum Damage, cancels, switches NP1 → N and advances the time. A solver with its own time control may still define run_solver(run::SolverRun{MySolverParams}, ctx::SolverContext). See src/Core/Solver/Solver_template/solver_template.jl.

A failed step is discarded. If the solver section has a Fallback, that solver recomputes the step from the last converged state and runs to the final time of the solver step; otherwise the run is cancelled:

Solver:
  Final Time: 1.0e-3
  Static:
    Maximum number of iterations: 50
  Fallback:
    Verlet:
      Safety Factor: 0.9

When the fallback takes over, each output keeps the time between two outputs, so a fallback with many short steps does not write every step. Fallback Output Frequency and Fallback Number of Output Steps in an output set the frequency for the fallback steps instead, like Output Frequency and Number of Output Steps do for the solver steps.

SolverParams selects the solver with a one_of field: options::SolverOptions = one_of(:solver) holds exactly one sub-section whose key is a registered solver name. Errors for a missing, a second or a misspelled solver come from one_of; schema, describe and the generated pages list the registered solvers.

The input reference lists every section and model with its keys; it is generated from the declarations (PeriLab.generate_parameter_docs). In a Julia session, PeriLab.describe("Correspondence Plastic") prints the keys of one model and PeriLab.describe("Correspondence Plastic"; template = true) a YAML block to start from. PeriLab.to_json_schema(PeriLab.InputDeck.PeriLabInput) returns a JSON Schema of the whole deck for editors.
